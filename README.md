# 番茄鐘時間管理小助理(Chrome 擴充套件)

一個只給自己用的 Chrome 擴充套件:把「中長期專案規劃」和「每天的輕量時間管理」接在一起,讓系統告訴你「現在該做什麼」,你只要專心做事。每天的時間可以用番茄鐘或碼錶計時、事後補登,也能排入會議和時段。

> 目前狀態:**設計和 Phase 1 資料結構都已定案,還沒開始寫程式。**

## 為什麼要做這個

日常工作裡,不同人會丟不同的工作過來,重要程度和截止日都不一樣。要自己一直記住「哪個先做、哪個快來不及」,還要另外寫工作日誌和 todo list,很耗腦力。

這個工具的目標是當一個**簡單的工作安排小助理**:

- 你設定好專案和規則,它幫你算每個時段該做什麼
- 快來不及時提早提醒你
- 每段工作結束時順手記一句,這就是工作紀錄,不用另外寫日誌
- 之後由 AI 看歷史紀錄,幫你調整排程規則

## 一天的使用情境

1. 早上打開擴充套件。系統依「每週工時範本」扣掉今天的會議和例行事項,算出今天真正能用的時間;今天要提早下班,就調整當天的上班時段。
2. 側邊欄的時間軸上會出現系統建議的時段規劃。想保護的時段(例如 10:00–11:30 專心做會員系統)可以鎖定。
3. 點開 popup 看「現在該做什麼」,用番茄鐘或碼錶開始計時。
4. 結束時寫一句「這段做了什麼、結果如何」。Task 做完了就手動標記完成。
5. 狀況一改變(做完、被插隊、多了一場會議),建議就重新計算,不會早上排好就固定不動。
6. 主管突然丟來一件急事?直接插入一筆「臨時工作」,馬上開始做。忘了計時的工作,事後補登就好。
7. 某個專案照目前進度會趕不上截止日,畫面就會跳出預警,由你決定要不要跟主管說。

## 核心概念

程式碼和文件一律使用下表的英文術語。正式定義以 [CONTEXT.md](./CONTEXT.md) 為準。

| 英文術語 | 中文 | 白話說明 |
|---|---|---|
| Project | 專案 | 一個接到的具體需求或工單。包含名稱、開始日、截止日(可以不填)、預估工作量和委託人。**做完由你手動標記**,完成後就不再排進時間 |
| Task | 任務 | 專案底下「朝同一個方向集中處理的一件事」,刻意不切太細。例如同一次 code review 抓到的幾個 bug 算同一個 Task。一個 Task 可以花好幾段工作時段、跨好幾天,**做完由你手動標記** |
| Work Session | 工作時段 | 在一個 Task 上實際花掉的一段時間,**只屬於一個 Task**。有三種記法:番茄鐘、碼錶(自訂長度)、事後補登。結束時寫一句備註,這就是工作紀錄;中途放棄或被插隊也會照實記下 |
| Requester | 委託人 | 丟工作給你的人(老闆、同事等)。清單只要建一次,每個人有預設權重,個別專案可以另外調整。每個專案都要選委託人,沒有人交辦的工作選系統內建的「自己」 |
| Schedule Weight | 排程權重 | 決定專案分到多少時間的分數,由「截止日緊迫度」、「委託人權重」和「你手動設的優先級」加權算出 |
| Weekly Work-Hours Template | 每週工時範本 | 平日每天的上班時段(例如 09:00–12:00、13:00–18:00),週末預設不上班。任何一天都能另外調整,例如提早下班或週末想做專案 |
| Commitment | 固定行程 | 會議、例行事項這類時間固定的事。手動輸入,可以是單次或每週重複,會先扣掉當天的可用時間 |
| Time Block | 時段 | 時間軸上分配給某個專案的一段時間。系統會自動建議,狀況改變就重排;你可以鎖定,鎖定的時段只做該專案的事 |
| Effort Estimate | 預估工作量 | 專案總共需要多少**動手做**的時間,會議不算。可以用小時或天輸入,系統換算成分鐘存。估計的時間用完、專案卻還沒做完時,會提醒你重新估計 |
| Must-Start-By | 最晚開始日 | 截止日減掉預估工作量,再減掉安全緩衝。到了這天,專案**每天保證至少分到基本時間** |
| Ad-hoc Task | 臨時工作 | 臨時被交辦、不屬於任何專案的工作,不用先建專案就能直接插入 |
| Interrupt Bucket | 臨時工作區 | 系統內建的特殊分類,專門放臨時工作 |
| Deadline Risk Warning | 逾期預警 | 預估會趕不上截止日時,提醒**你自己**的警示 |
| Override | 調整紀錄 | 你沒照系統建議做的時候(改做別的 Task、鎖定時段),記下系統的建議和你實際的選擇 |
| Proposal | 建議 | AI 想修改的內容。會寫進建議收件匣,你同意了才套用(Phase 2 起) |

## 排程規則怎麼算

**1. 今天有多少時間**
從每週工時範本(或當天調整過的時段)扣掉固定行程,就是今天能用來工作的時間。

**2. 建議時段和「現在該做什麼」**
系統依規則把可用時間分給各個專案,排成建議時段,顯示在時間軸上。每次狀況改變(做完、插隊、新增會議)都會重新計算,不會一早排好就固定。按「現在該做什麼」時,系統依當下狀態挑出下一個 Task。這一層是**純規則計算,不用 AI**。

**3. 鎖定時段**
你可以把某個時段鎖定給特定專案,直接拖動建議時段也算鎖定。在鎖定的時段裡,系統只從這個專案的 Task 挑下一件事;時段以外照常計算。

**4. 優先順序**
- 已經過了最晚開始日的專案先處理,保證每天拿到基本份額
- 剩下的時間依排程權重的分數高低分配
- 如果好幾個專案同時需要保底,加起來超過當天的時間,就依排程權重排序,先滿足分數高的;沒分到時間的專案會觸發逾期預警

**5. 臨時工作**
- 插入後直接佔用當下的時間,也算進當天已經用掉的時間;原本正在計時的工作時段會記成「被中斷」
- 統計報表中**和原本規劃的工作分開計算**,不會算成專案進度
- 事後發現其實是長期工作的話,可以升級成正式專案

**6. 會議和專案**
會議可以連結專案。週報裡會算進這個專案花的時間,但**不會扣**專案的剩餘工作量,因為預估工作量只算實際動手做的時間。
會議照排定的時間計算,不用事後確認;如果會議提早結束、你已經開始計時工作,重疊的部分算工作時間。

**7. 沒有截止日的專案**
不計算最晚開始日、截止日緊迫度和逾期預警,只依委託人權重和手動優先級排序。

**8. 調整紀錄**
你沒照建議做(改做別的 Task、鎖定時段)時,就會存一筆調整紀錄。Phase 1 只負責存,Phase 3 才拿來分析、調整權重。

## 逾期預警

下面兩個條件**只要有一個成立**就會發出預警:

| 條件 | 意思 | 設定方式 |
|---|---|---|
| 延遲天數 | 預估完成日比截止日晚超過 N 天 | 全域預設 0 天(只要會延遲就提醒),個別專案可以另外調整 |
| 時間不足比例 | 從現在到截止日還能投入的時間,低於剩餘工作量的某個百分比 | 全域預設 120%,個別專案可以另外調整 |

預警**只會顯示給你自己看**,不會自動寄信或發訊息給主管。要不要說、怎麼說,由你決定。

## 畫面

用可以實際操作的原型比較過三種主畫面(原型保存在 `prototype/ui-variants` 分支,不放在主線),結論如下:

- **平常使用:Popup 專注卡。** 點 Chrome 工具列圖示跳出小視窗,只顯示「現在該專心處理的那一件事」,可以用番茄鐘或碼錶開始;臨時工作、事後補登、逾期預警、今天可用時間也收在這個小視窗裡。
- **想看今天全貌時才打開:側邊欄時間軸。** 在 Chrome 側邊欄把今天做過的、正在做的、固定行程,以及建議或鎖定的時段排成一條時間線;可以在這裡鎖定時段、回顧備註、補登工作。不需要整天開著。
- **設定集中在選項頁(options page)。** 專案、Task、委託人、每週工時範本、固定行程、逾期預警門檻,以及「連接資料夾」授權,都在選項頁用簡單的表單編輯。popup 和側邊欄只負責日常執行。
- **不做:整頁規劃總覽。** 以專案表格為主的整頁畫面不保留。

## 資料放在哪裡

- 只做 **Chrome 桌面版**。手機版以後另外開發,讀同一種資料格式。
- 擴充套件平常把資料存在 Chrome 內建的儲存空間(`chrome.storage.local`),速度快,也不用額外授權。
- 那個空間 AI 工具讀不到,所以要在設定頁按一次「連接資料夾」,擴充套件就會定期把資料寫成一般的 JSON 檔,存到專案的 `./data` 資料夾。**AI 工具讀的是這份 JSON。**
- AI 不會直接修改資料。Phase 1 只讀;Phase 2 起,AI 想改什麼就寫進「建議收件匣」檔案,擴充套件讀進來給你確認,你同意了才套用。詳見 [ADR 0003](./docs/adr/0003-ai-changes-via-proposal-inbox.md)。
- 缺點:Chrome 完全關掉再打開後,可能要回設定頁再按一次授權,這是 Chrome 的安全限制。
- 每種資料有哪些欄位、檔案怎麼切,見 [Phase 1 資料結構](./docs/data-model.md)。

詳見 [ADR 0002](./docs/adr/0002-storage-and-ai-readable-sync.md)。

## AI 怎麼參與

- **擴充套件本身**只負責記錄資料,並提供一個「請 AI 檢視排程」的手動按鈕。
- Chrome 擴充套件在瀏覽器關閉時無法執行,也收不到外部通知。所以之後如果要從定時排程、Slack、專案管理軟體等地方**觸發 AI 檢視**,會交給另一個在電腦上獨立執行的小程式(**Companion Process**)處理。它讀取同一份 `./data`,想修改資料時一樣要透過建議收件匣。
- AI 檢查的是「排程規則本身合不合理」,不會取代排程引擎的規則計算。

詳見 [ADR 0001](./docs/adr/0001-extension-plus-companion-process.md)。

## 開發階段

| 階段 | 內容 |
|---|---|
| Phase 1 | 專案、Task、委託人設定;每週工時範本和固定行程;規則式排程(建議時段、鎖定時段、算下一件事);工作時段(番茄鐘、碼錶、事後補登)和備註;臨時工作;逾期預警;調整紀錄;把資料匯出成 `./data` 的 JSON。**不含 AI** |
| Phase 2 | 接入 AI(Claude / Codex)檢視排程規則合不合理;加入 Companion Process,讓觸發方式可以擴充;建議收件匣;從 Google 日曆或 Outlook 匯入行程 |
| Phase 3 | AI 每週時間利用報告;依調整紀錄自動修正排程權重;動態排程 |

## 刻意不做的事

- 多人、多帳號:只有自己用,「委託人」只是標籤加上權重
- 另外的工作日誌或 todo list:工作時段的備註就是紀錄
- 自動通知主管
- 把 Task 切成很細的子任務
- 事先把 Task 排死在固定時間:時段只保留給專案,Task 仍然即時挑選
- Phase 1 的排程計算使用 AI
- Phase 1 從日曆自動匯入行程

## 還沒決定的事

- 排程引擎的細節:截止日緊迫度的公式,以及最晚開始日和逾期預警要不要扣掉其他專案分走的時間(見[資料結構](./docs/data-model.md)最後的注意事項)
- Companion Process 用什麼技術開發
