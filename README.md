# 番茄鐘時間管理小助理(Chrome 擴充套件)

一個只給自己用的 Chrome 擴充套件:把「中長期專案規劃」和「每天的番茄鐘執行」接在一起,讓系統告訴你「現在該做什麼」,你只要專心做事。

> 目前狀態:**設計已定案,還沒開始寫程式。**

## 為什麼要做這個

日常工作裡,不同人會丟不同的工作過來,重要程度和截止日都不一樣。要自己一直記住「哪個先做、哪個快來不及」,還要另外寫工作日誌和 todo list,很耗腦力。

這個工具的目標是當一個**簡單的工作安排小助理**:

- 你設定好專案和規則,它幫你算每個時段該做什麼
- 快來不及時提早提醒你
- 番茄鐘結束時順手記一句,這就是工作紀錄,不用另外寫日誌
- 之後由 AI 看歷史紀錄,幫你調整排程規則

## 一天的使用情境

1. 早上打開擴充套件。系統依「每週工時範本」知道今天有多少時間可用;今天要提早下班,就手動調一下。
2. 按「現在該做什麼」,系統依規則挑出最該做的 Task,開始一個番茄鐘。
3. 番茄鐘結束,寫一句「這段做了什麼、結果如何」。Task 做完了就手動標記完成。
4. 再按一次「現在該做什麼」。每次都依最新狀況重新計算,不是早上排好一張固定清單。
5. 主管突然丟來一件急事?直接插入一筆「臨時工作」,馬上開始做。
6. 某個專案照目前進度會趕不上截止日,畫面就會跳出預警,由你決定要不要跟主管說。

## 核心概念

程式碼和文件一律使用下表的英文術語。正式定義以 [CONTEXT.md](./CONTEXT.md) 為準。

| 英文術語 | 中文 | 白話說明 |
|---|---|---|
| Project | 專案 | 一個接到的具體需求或工單。包含名稱、開始日、截止日(可以不填)、預估工作量和委託人 |
| Task | 任務 | 專案底下「朝同一個方向集中處理的一件事」,刻意不切太細。例如同一次 code review 抓到的幾個 bug 算同一個 Task。一個 Task 可以做好幾個番茄鐘、跨好幾天,**做完由你手動標記** |
| Pomodoro Session | 番茄鐘 | 一段專心工作的時間,**只屬於一個 Task**。結束時寫一句備註,這就是工作紀錄 |
| Requester | 委託人 | 丟工作給你的人(老闆、同事等)。清單只要建一次,每個人有預設權重,個別專案可以另外調整 |
| Schedule Weight | 排程權重 | 決定專案分到多少時間的分數,由「截止日緊迫度」、「委託人權重」和「你手動設的優先級」加權算出 |
| Weekly Work-Hours Template | 每週工時範本 | 平日每天幾點到幾點可以工作,週末預設休息。任何一天都能手動調整,例如提早下班或週末想做專案 |
| Effort Estimate | 預估工作量 | 專案至少要幾個工作天或幾個番茄鐘才做得完 |
| Must-Start-By | 最晚開始日 | 截止日減掉預估工作量,再減掉安全緩衝。到了這天,專案**每天保證至少分到基本時間** |
| Ad-hoc Task | 臨時工作 | 臨時被交辦、不屬於任何專案的工作,不用先建專案就能直接插入 |
| Interrupt Bucket | 臨時工作區 | 系統內建的特殊分類,專門放臨時工作 |
| Deadline Risk Warning | 逾期預警 | 預估會趕不上截止日時,提醒**你自己**的警示 |
| Override | 調整紀錄 | 系統建議的做法和你實際採用的做法不一樣時,記錄兩者的差異 |

## 排程規則怎麼算

**1. 今天有多少時間**
從每週工時範本算出今天可用的番茄鐘數量,你隨時可以手動調整當天的數字。

**2. 每次問「現在該做什麼」都重新計算**
系統不會一早排好整天的清單。每做完一個番茄鐘或 Task,它會依最新狀況(剩多少時間、哪些做完了、有沒有插入臨時工作)重新挑出下一件事。這一層是**純規則計算,不用 AI**。

**3. 優先順序**
- 已經過了最晚開始日的專案先處理,保證每天拿到基本份額
- 剩下的時間依排程權重的分數高低分配
- 如果好幾個專案同時需要保底,加起來超過當天的時間,就依排程權重排序,先滿足分數高的;沒分到時間的專案會觸發逾期預警

**4. 臨時工作**
- 插入後直接佔用當下的番茄鐘,也算進當天已經用掉的時間
- 統計報表中**和原本規劃的工作分開計算**,不會算成專案進度
- 事後發現其實是長期工作的話,可以升級成正式專案

**5. 沒有截止日的專案**
不計算最晚開始日、截止日緊迫度和逾期預警,只依委託人權重和手動優先級排序。

**6. 調整紀錄**
系統建議的做法和你實際的做法不同時,就會存一筆調整紀錄。Phase 1 只負責存,Phase 3 才拿來分析、調整權重。

## 逾期預警

下面兩個條件**只要有一個成立**就會發出預警:

| 條件 | 意思 | 設定方式 |
|---|---|---|
| 延遲天數 | 預估完成日比截止日晚超過 N 天 | 全域預設 0 天(只要會延遲就提醒),個別專案可以另外調整 |
| 時間不足比例 | 從現在到截止日還能投入的時間,低於剩餘工作量的某個百分比 | 可以設定門檻 |

預警**只會顯示給你自己看**,不會自動寄信或發訊息給主管。要不要說、怎麼說,由你決定。

## 資料放在哪裡

- 只做 **Chrome 桌面版**。手機版以後另外開發,讀同一種資料格式。
- 擴充套件平常把資料存在 Chrome 內建的儲存空間(`chrome.storage.local`),速度快,也不用額外授權。
- 那個空間 AI 工具讀不到,所以要在設定頁按一次「連接資料夾」,擴充套件就會定期把資料寫成一般的 JSON 檔,存到專案的 `./data` 資料夾。**AI 工具讀寫的是這份 JSON。**
- 缺點:Chrome 完全關掉再打開後,可能要回設定頁再按一次授權,這是 Chrome 的安全限制。

詳見 [ADR 0002](./docs/adr/0002-storage-and-ai-readable-sync.md)。

## AI 怎麼參與

- **擴充套件本身**只負責記錄資料,並提供一個「請 AI 檢視排程」的手動按鈕。
- Chrome 擴充套件在瀏覽器關閉時無法執行,也收不到外部通知。所以之後如果要從定時排程、Slack、專案管理軟體等地方**觸發 AI 檢視**,會交給另一個在電腦上獨立執行的小程式(**Companion Process**)處理。它和擴充套件讀寫同一份 `./data`。
- AI 檢查的是「排程規則本身合不合理」,不會取代每次「算下一件事」的規則計算。

詳見 [ADR 0001](./docs/adr/0001-extension-plus-companion-process.md)。

## 畫面

用可以實際操作的原型比較過三種主畫面(原型保存在 `prototype/ui-variants` 分支,不放在主線),結論如下:

- **平常使用:Popup 專注卡。** 點 Chrome 工具列圖示跳出小視窗,只顯示「現在該專心處理的那一件事」和開始按鈕;臨時工作、逾期預警、今日產能也收在這個小視窗裡。
- **想看今天全貌時才打開:側邊欄時間軸。** 在 Chrome 側邊欄把今天做過的、正在做的、預估接下來要做的排成一條時間線,可以回顧備註、補登臨時工作(輸入框固定在最下方)。不需要整天開著。
- **設定集中在選項頁(options page)。** 專案、Task、委託人、每週工時範本、逾期預警門檻,以及「連接資料夾」授權,都在選項頁用簡單的表單編輯。popup 和側邊欄只負責日常執行。
- **不做:整頁規劃總覽。** 以專案表格為主的整頁畫面不保留。

## 開發階段

| 階段 | 內容 |
|---|---|
| Phase 1 | 專案、Task、委託人設定;每週工時範本;規則式排程(算下一件事);番茄鐘與備註;臨時工作;逾期預警;調整紀錄;把資料同步成 `./data` 的 JSON。**不含 AI** |
| Phase 2 | 接入 AI(Claude / Codex)檢視排程規則合不合理;加入 Companion Process,讓觸發方式可以擴充 |
| Phase 3 | AI 每週時間利用報告;依調整紀錄自動修正排程權重;動態排程 |

## 刻意不做的事

- 多人、多帳號:只有自己用,「委託人」只是標籤加上權重
- 另外的工作日誌或 todo list:番茄鐘的備註就是紀錄
- 自動通知主管
- 把 Task 切成很細的子任務
- Phase 1 的排程計算使用 AI

## 還沒決定的事

- `./data` 裡 JSON 檔的具體結構
- AI 修改 `./data` 之後,怎麼同步回擴充套件,以及兩邊都改了要以誰為準
- JSON 同步的頻率
- Companion Process 用什麼技術開發
- 番茄鐘和休息時間的預設長度
- 安全緩衝、時間不足比例門檻、各權重因子的預設值
- 時間不足比例門檻能不能在個別專案另外設定
