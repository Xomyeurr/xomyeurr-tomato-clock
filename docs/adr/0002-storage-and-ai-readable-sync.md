# chrome.storage.local as source of truth, synced to a plain JSON file for AI readability

Chrome Extension data needs to be readable/writable by a local AI agent (e.g. Claude Code), which the user wants stored in a local folder for simple install and maintenance. Research found that `chrome.storage.local` is fast and always available without permission prompts, but it is Chrome's internal LevelDB profile storage — not a real file an outside process can parse. The File System Access API can write a real file to a user-chosen folder, but only works from an extension page with a DOM and a user gesture (not the service worker), and the permission grant is not guaranteed to survive a full browser restart.

We decided `chrome.storage.local` stays the extension's source of truth for day-to-day reads/writes, and the options page offers a one-time "connect folder" step (File System Access API) that periodically syncs the data out to a plain JSON file under `./data`. That JSON file — not `chrome.storage.local` — is what the Companion Process and any AI agent read; how their changes flow back is decided in ADR 0003. Trade-off: after a full browser restart, the user may need to revisit the options page once to re-grant folder access before syncing resumes.
